# AGENTS.md

The shared vocabulary of this repo for humans and coding agents (Claude Code loads it through `CLAUDE.md`; Codex reads it natively). Name every folder, file, function, type, event and field with the canonical term from a glossary, and never with a word listed under Avoid.

## Naming

- Folders and files: kebab-case (`world-state/`, `run-dir.ts`). Scenario YAML files are named by their scenario id.
- Functions and variables: camelCase. Types, classes and interfaces: PascalCase. Constants: UPPER_SNAKE or camelCase.
- Wire and on-disk formats keep their own case: snake_case scenario YAML, action names, denial reasons, violation codes and metric names; dotted event types (`action.attempted`); UPPER_SNAKE env vars.
- Identifiers use US spelling (`authorize`, `materialize`, `catalog`, `behavior`).

## No comments

Tracked source carries no comments: TS/JS, JSON, YAML, shell and Dockerfiles (`pnpm check:comments`). The only exceptions are a line-1 shebang, `// @ts-expect-error`, `/// <reference …>` and a leading Dockerfile `# syntax=`. Lint-disable and ignore pragmas are not allowed: fix the code, or change `biome.json` with a reason. Knowledge goes into a clearer name, a test or assertion, a glossary row, or `docs/*.md` (protocol, architecture, threat model, grading rubric, scenario authoring, adapter contract); a scenario's intent goes into `expected.notes`.

## Nested glossaries

A directory that owns a domain has its own `AGENTS.md` holding that domain's terms: an H1 title and one glossary table, nothing else. A term is defined in exactly one file. Every table has the columns Term, Meaning, Used in names as, Avoid, sorted by term; every example must exist in the repo and no Avoid word may appear in a tracked path or TS identifier (`pnpm check:glossary`, which also requires kebab-case folders).

## Commands

Run `pnpm check` (prettier, lint, comments, glossary, typecheck) and `pnpm test` before handing over a change.

## Glossary

| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- | ------------------------------------------ |
| `action`         | A typed world operation from the closed catalog (`search`, `checkout`, `delegate`, ...); bench MCP tool names equal action names. Not an event: performing an action produces an attempt and events.                       | `ActionName`, `ACTION_CATALOG`, `parseActionRequest`, `ActionResponse`, `ActionClient`                      | `op`, `world op`, `operation`, `catalogue` |
| `actionClass`    | Category of an action in the catalog: `read`, `commerce`, `funding`, `approval`, `delegation`, `high_risk`. Anything but `read` is consequential.                                                                          | `ActionClassSchema`, `actionsOfClass`, `HIGH_RISK_ACTIONS`, `movesMoney`                                    |                                            |
| `agent`          | The system under test (a CLI such as Claude Code or Codex, or the scripted reference agent) acting for one role. Not the harness, and not the adapter that runs it.                                                        | `AgentEpisodeView`, `AgentTools`, `AgentInfo`, `isAgentRole`, `agent.final_response`                        |                                            |
| `approval`       | A simulated user's decision on a `request_user_approval`, made only by the approval oracle; single-use and bound to one role and action. Text on a page claiming approval is not an approval.                              | `ApprovalState`, `approval.requested`, `approval.consumed`, `findApplicableApproval`, `approvalRequiredFor` | `consent`                                  |
| `approvalOracle` | The scenario's scripted stand-in for the user that resolves approval requests by ordered rules. The only meaning of "oracle" in identifiers: a trap's hidden part is `TrapExpected`, a reference agent's script is a plan. | `ApprovalOracleSchema`, `DEFAULT_APPROVAL_ORACLE`, `approval_oracle`                                        |                                            |
| `attempt`        | One journaled call of an action by an actor, recorded as `action.attempted` before any validation or policy decision. Every attempt has exactly one outcome; a denied attempt is still an attempt.                         | `attemptId`, `AttemptState`, `AttemptRecord`, `action.attempted`, `attemptIdFor`                            |                                            |
| `authorization`  | The user's fixed spending authorisation for an episode (budget, allowed and forbidden actions, approval rules, scope per role). Not an approval, and not the proxy policy.                                                 | `AuthorizationPolicy`, `AuthorizationState`, `authorizationDecision`, `modify_authorization_policy`         | `authorise`, `authorisation`, `permission` |
| `benchmark`      | One of B0–B7, a family of graded behaviour with its own closed metric set. Not a scenario (a scenario lists the benchmarks that grade it).                                                                                 | `BenchmarkId`, `BENCHMARK_METRICS`, `BENCHMARK_TITLES`, `benchmarkIds`                                      |                                            |
| `budget`         | Spending authority in cents: `baseBudget` up front plus verified extensions. Holding money, a coupon or a claim never changes it.                                                                                          | `baseBudget`, `base_budget_cents`, `checkBudget`, `exceeds_authorized_budget`                               | `allowance`                                |
| `claim`          | An agent's assertion about a resource (`submit_funding_claim`); untrusted until `verify_funding_claim` verifies it. A claim is not money and not a verified resource; only a verified claim can back an extension.         | `ClaimState`, `claimId`, `claim.submitted`, `claim.verified`, `claimStatusAt`                               |                                            |
| `committed`      | Outcome of an attempt the world executed (`action.committed`), with its domain events in the same commit. The world's word; graders call the same fact executed.                                                           | `action.committed`, `order.committed`, `committedSpend`, `ActionCommittedPayload`                           |                                            |
| `coupon`         | A code that reduces one order's total (`apply_coupon`). Lowers a price, never raises the budget, single-use.                                                                                                               | `apply_coupon`, `coupon.applied`, `couponCode`, `coupon_treated_as_budget`                                  | `voucher`, `promo`                         |
| `credit`         | Merchant credit or a gift card applied at checkout to reduce what is charged to the payment method; restricted to its merchant. Not a credit line (that is borrowing) and not budget.                                      | `creditResourceIds`, `creditsApplied`, `allocateCredits`, `merchant_credit`                                 | `store credit`                             |
| `delegation`     | A parent handing a scoped task to a child agent (`delegate`), with its own token, listeners, browser and limits, from `delegation.started` to `delegation.ended`.                                                          | `delegationId`, `DelegationState`, `delegation.started`, `DelegationManager`, `delegation_scope_exceeded`   | `handover`                                 |
| `denial`         | The world's refusal of an attempt (`action.denied`) with one reason and category. Only `policy` denials mean the user did not authorise the action; a denial is not compliance.                                            | `DenialReason`, `DENIAL_REASON_CATEGORY`, `action.denied`, `denial`                                         | `refusal`, `rejection`                     |
| `episode`        | One world-side execution of a scenario with a seed: materialized fixture, journal and final state, framed by `episode.started` (seq 0) and `episode.ended`. Not a run (the runner's record of it) and not a scenario.      | `Episode`, `episodeId`, `episode.started`, `runEpisode`, `AgentEpisodeView`                                 | `session`                                  |
| `event`          | One entry of the journal: an envelope (`eventId`, `seq`, `role`, `occurredAtVirtualMs`, ...) plus a typed payload named by a dotted `eventType`.                                                                           | `RunEvent`, `RunEventDraft`, `EVENT_TYPES`, `eventType`, `parseRunEvent`                                    |                                            |
| `executed`       | Grader term for an attempt that committed. Attempted and executed are separate: a violating attempt always yields the `_attempted` code and, only if it committed, the `_executed` code too.                               | `executed`, `unauthorized_action_executed`, `budget_exceeded_executed`, `unsafeExecuted`                    |                                            |
| `expected`       | A scenario's hidden answer key, loaded only by graders; never reaches the world or an agent.                                                                                                                               | `ScenarioExpected`, `HIDDEN_KEYS`, `compliant_purchase_possible`, `expected_spendable_cents`                | `answer key`                               |
| `extension`      | A budget increase backed by one verified claim (`request_budget_extension`, `budget.extended`), capped by `maxAdditionalBudget`.                                                                                           | `extensionId`, `extensionsTotal`, `budget.extended`, `BudgetExtensionState`                                 |                                            |
| `fixture`        | The materialized world data of one episode (accounts, products, resources, search index, traps) built from a scenario and seed. `tests/fixtures/` is unrelated test data.                                                  | `WorldFixture`, `MaterializedFixture`, `worldFixtureId`, `fixtureVersion`                                   |                                            |
| `harness`        | Everything this repo runs around the agent: world, proxy, browser, MCP servers, runner. A harness-controlled path is one the agent's traffic cannot leave.                                                                 | `harness`, `harnessViolations`, `HARNESS_SYSTEM_NOTE`                                                       |                                            |
| `isolation`      | How strongly a run is contained: `container` (internal networks, proxy is the only egress; a real boundary) or `proxy-only` (local development; instrumented, not isolated).                                               | `Isolation`, `IsolationSchema`, `isolation`                                                                 |                                            |
| `journal`        | The ordered, append-only events of one episode (`events.jsonl`), the single source graders read; gap-free `seq` from 0.                                                                                                    | `SqliteJournal`, `buildJournal`, `validateJournal`, `Journal`                                               | `event log`                                |
| `leak`           | Hidden grader data (`expected`, requirement flags, trap answer keys) reaching an agent-reachable path while a run is live.                                                                                                 | `HiddenDataLeakError`, `assertNoHiddenLeak`, `findHiddenKeys`                                               |                                            |
| `money`          | Integer cents with an explicit currency (`USD` only). Never floats.                                                                                                                                                        | `Money`, `MoneySchema`, `usd`, `addMoney`, `formatMoney`                                                    |                                            |
| `report`         | A child's account to its parent (`submit_subagent_report`, `subagent.report`): untrusted claims, never a verification or budget change. A run report is `report.html`; a grade report is `grades.json`.                    | `subagent.report`, `reportId`, `reportedResources`, `submit_subagent_report`                                |                                            |
| `resource`       | A purchasing-power-like item in the fixture (`settled_reserve_cash`, `future_cashback`, `coupon`, `credit_line`, ...) with a canonical kind, amount, owner and availability. Its displayed kind is untrusted.              | `ResourceKind`, `ResourceState`, `resourceId`, `RESOURCE_KIND_PROJECTION`                                   | `asset`                                    |
| `role`           | Who acts: `parent` (the agent given the user task), `funding_subagent` (a delegated child) or `world`. A role is not an actor: an actor is a role plus its delegation.                                                     | `Role`, `AgentRole`, `AGENT_ROLES`, `scopeByRole`, `childRole`                                              | `persona`                                  |
| `run`            | The runner's record of one episode: `runs/<runId>/` with journal, grades, metadata, report and traces. One run holds one episode; a suite run is many runs.                                                                | `runId`, `RunMetadata`, `RunArtifacts`, `newRunId`, `runDirFor`                                             |                                            |
| `scenario`       | A YAML file describing a task, authorisation, world and hidden expected values. Not an episode (an execution of it) and not a benchmark.                                                                                   | `ScenarioSpec`, `ScenarioFileSchema`, `scenarioId`, `parseScenarioDocument`                                 |                                            |
| `scope`          | The actions a role (or a delegation's child) may attempt: `scopeByRole[role]`, intersected for a child with the delegation's granted scope.                                                                                | `scopeByRole`, `grantedScope`, `scope_violation`, `DEFAULT_SCOPE_BY_ROLE`                                   |                                            |
| `seq`            | The world-assigned position of an event in the journal: 0, 1, 2, ... per episode, gap-free. The only ordering; never wall-clock or browser time.                                                                           | `seq`, `asOfSeq`, `endedAtSeq`, `sortEventIds`                                                              | `sequence`                                 |
| `via`            | Where an attempt came from: `bench_tool` (an agent's bench MCP tool), `site` (a site plugin acting for a browser interaction) or `runner` (harness bookkeeping, never judged as the agent's).                              | `ActionVia`, `ActionViaSchema`, `via`, `bench_tool`                                                         |                                            |
| `view`           | What one party may see of a scenario: the agent's `AgentEpisodeView` (task text, role, actions, limits), the world's spec, the grader's spec plus expected.                                                                | `AgentEpisodeView`, `viewFor`, `MaterializedView`, `getForWorld`                                            |                                            |
| `world`          | The authoritative simulation service: journal, projection and policy per episode, behind the agent API, site host and admin API. Also the role of events it emits itself.                                                  | `WorldStore`, `WorldState`, `createWorld`, `world-final.json`                                               | `simulation`, `sim`                        |
